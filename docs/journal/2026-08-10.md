## `W-037` — `label-offset`, the escape hatch out of automatic label placement

**What.** A `label-offset` property (alias `text-offset`), valid on both nodes and edges, taking two
numbers in user units — positive right and down, the second optional.

- `src/props.rs` — the two `PropDef`s, so `check`, completion and `docs/reference.md` all learn it
  at once
- `src/style.rs` — `label_offset: Option<(f64, f64)>` through the cascade, parsed in the one
  `apply_prop` arm the convention asks for
- `src/render_svg.rs` — six sites: `place_label`, the pin, `bounds`, `group_frame`, `node_label`
- `src/tests.rs` — four tests: the pin holds, a moved label still displaces the next one, the
  viewBox follows a label moved outside its shape, and the property cascades like any other
- `docs/language.md` — a *Moving a label* section with two examples, both parsed and rendered by
  the suite (`X-015`)
- `docs/reference.md` — regenerated from the tables

**Why.** `X-006` says edge labels avoid lines, not each other's readability, and that the solver is
local: nothing guarantees the best global arrangement. On a busy diagram it runs out of room. The
answer taken here is an escape hatch rather than a better cost function — the author can see what
the cost function cannot, and a declared position is a decision. Hence the pin: on an edge, an
offset stops the avoidance from second-guessing it, so the label does not drift when a neighbouring
edge changes.

**Impact.** `X-006` stays `mitigated` and now names its escape hatch. No behaviour changes for a
file that does not use the property; the SVG for every example is byte-identical.

## Second pass — the ideas and questions the first pass left standing

The first pass moved eleven ideas but left four things unresolved, three of them because they were
never put to anyone.

**`D-023` — one keyword per slot form.** `Q-004` was answered the same day it was opened. An
archetype needing a second positional shape declares a second word for it (`point a "A" 3` spreads
across the axis, `pair a "A" 3 7` reads coordinates) rather than dispatching on how many values were
written, or on a mode property set elsewhere. Arity-dispatch cannot separate two forms of the same
length and leaves the diagnostic unable to name which was meant; a mode property makes one line mean
two things depending on a setting written somewhere else, which is what `D-005` refuses everywhere
else. It is `D-015` applied *inside* an archetype rather than only between them — so `D-015` is now
`amended`, and it costs a word of vocabulary and nothing in either grammar. `W-048` is the first to
use it.

**`Q-002` restored.** "Which archetype after `pie` and `packet`?" had been **deleted** from the index

explicit. A deleted question reads as a question nobody ever asked. Recovered from
`git log -S` and re-filed as `answered`: `W-016` … `W-026` all landed, so the ordering question
stopped having a subject.

## Two chantiers carried an undecided design — decided before starting

Preparing the work order surfaced that `W-047` and `W-045` were not chantiers but questions wearing
a chantier's clothes. Both were settled by looking at the code rather than at taste.

**`D-024` — an activation bar is a block.** `activate api { … }` is a `group` whose `edge_members`
are the messages the bar spans. The mechanism was already built and already right: a group records
`members` **and** `edge_members`, and a sequence frame spans message *rows* — which is exactly a
bar's extent. Nesting comes free. The alternative, inferring a bar from a call and its matching
reply, was refused because "matching" is a guess the moment two calls are in flight, and a silent
guess is what `D-005` exists to prevent.

**`D-025` — a pin is a member line, a wire carries its pins as positional data.** `- 1: +12V` is
`W-013`; `j1 -> j2 "power" 1 3` is `W-015`. No grammar moves.

The dotted form `j1.3` was the obvious answer and it is wrong for a reason worth writing down:
`ident` forbids `.` and `3` is not an identifier, so `j1.3` does not parse at all — but `j1.p3`
**does**, as `ident` + `class_ref`. The most readable syntax available is the one that already means
*a class reference*. Choosing it would have bought a pretty example and an ambiguity in both
grammars.

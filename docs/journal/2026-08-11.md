# 2026-08-11

The dated state of the project lives in [`../INDEX.md`](../INDEX.md); this file records what a
session *did*, which the index deliberately does not.

One session, five pieces of work. The index went in first — the licence question closed, the
parked idea promoted, the two open risks each given a chantier — and everything after it was
carrying that out.

## `D-032` / `Q-005` — the licence is proprietary, and that is an answer

`D-020` said proprietary on 2026-07-31 and `Q-005` had stayed open since, because the whole
distribution half was built afterwards: the wasm playground (`W-096`), the release binaries and CI
action (`W-097`), the Markdown preview (`W-098`), the Typst plugin (`W-099`). All four work. None
of them ship.

Recorded as a **decision** rather than as a question quietly closed. The four will keep prompting
the same question from anyone who finds them, and a repository that answers "we never decided"
invites somebody to decide it by accident. Nothing in the tree changes: `LICENSE` grants nothing,
`Cargo.toml` keeps `publish = false`, and the test asserting `release.yml` creates no release and
runs no `cargo publish` is now load-bearing rather than precautionary.

## `W-103` — the treeview draws its links where the boxes are not

**What.** `charts.rs` treated `TreeKind::View` exactly like `TreeKind::Mind`: a diagonal from the
parent's right edge to the child's left. On indented rows that crosses every row between the two
and runs *behind* the boxes, because nodes are painted after polylines. So the structure of the
tree was the one thing the drawing hid.

A trunk in the gutter the indent reserves, a short elbow into each row, and the trunk stopping at
the **last** child.

**Why the last child matters.** It is not decoration. Every row between a parent and its last child
is one of its descendants, so it is indented past the trunk — which is what turns "a guide is never
behind a box" from a hope into a property. The test asserts that property over every segment
against every box rather than checking the picture, and it was **proven by reverting the fix**: it
names the guide, its coordinates and the box it crosses.

## `W-104` — `fmt --migrate`, and `X-008` retired

**What.** `bgraph fmt --migrate` folds a removed `opacity` into the alpha of every paint in its
block. `D-016` took the property out because transparency belongs to the paint; that was right, and
it was also a breaking change that had stayed open on the strength of "the message names the fix" —
which is true, and is not a migration.

Surgical rather than a reprint: the alpha digits go into the colour where it stands and the
declaration is cut out, so a comment on the same line and a column lined up by hand both survive.
The existing alpha is **multiplied** rather than replaced, because an element opacity and a paint
alpha composited.

**Two refusals, one principle** — this may move a value, it may not decide one. A block with no
colour to carry the alpha, and a named colour like `tomato`, which has no fourth channel. Both name
the line.

`--migrate` is a second mode and not a side effect of formatting: a diff that both migrated and
reflowed would be unreviewable, which is the same reason `fmt` leaves interior alignment alone.

## `W-105` — an `ortho` edge goes around the boxes, and `X-004` is retired

**What.** A\* over a grid of the only lines an orthogonal path ever turns on — a channel either
side of every box, plus the two centre lines being joined — with a price on corners.

**The corner price is the design.** Shortest alone treats every staircase of the same length as
equally good, and the one it happens to find is the ugly one.

**Determinism was the risk, not the search.** The golden test compares byte for byte and this
project has already shipped a diagram that rendered differently run to run (`W-065`, a `HashMap` in
the venn). So costs are `i64` thousandths, ties go to the state index, and there is no hash
container in the module. A test renders the same source nine times; a second declares the same
boxes in another order.

**It can decline** — past sixty boxes, or where no path exists — and then keeps the old elbow so
`check::after_layout` can report the crossing. A drawing that admits it is wrong beats a missing
edge, and `W-064`'s diagnostic did not become wrong, it became rare.

**The clearance is 16 because 8 looked wrong.** The detour ran close enough over a box that the
arrow head of the edge *terminating* on it had nowhere to sit.

**Not one checked-in SVG moved**, because no example used `ortho` — so the feature would have
shipped with nothing to look at. `examples/ortho.bd` is the worked case, and it also shows the
limit this leaves behind, recorded as `X-018`: the router avoids boxes, not other edges.

## `W-102` — `type bpmn`, the twenty-ninth genre

**What.** The core, pools and lanes as `group`s, typed event triggers, sub-processes, boundary and
intermediate events, data artefacts. `I-021` had been parked for exactly one day because BPMN is
mostly ceremony and nobody had chosen which part is useful; the choice was wide.

**Four words** — `task`, `event`, `gateway`, `data` — which is `D-023` read at its widest. Four
things carry four shapes of data, and no count of values after the label could tell a task's one
word from a gateway's one word. On the free path, per the `W-043` precedent.

**A prediction that was wrong, in the useful direction.** The tasklist said boundary events would
need a language decision: an event attached to the *edge* of a task wants an anchor on a box's
perimeter, and `D-001` has no vocabulary for one. On building it, an `attach` property naming the
host was enough — and it is declared placement like every other, since the author says which box
and where on it is a fixed rule rather than something solved. No question came back.

Three things building it turned up, all of them older than it:

- **The free path read the wrong slots.** It resolved positional values against the archetype's
  *primary* slots rather than the word the author wrote. Invisible from `W-048` until now, because
  `xy` was the only genre with a second word and `xy` is a chart, so it never came through there.
- **There was no layer for a mark inside a shape.** Every polyline in the engine is drawn before
  the boxes, so a gateway's cross rendered behind an opaque diamond — which looks exactly like
  "the glyph code never ran". `Polyline::over` splits the pass in both writers.
- **The router needed a rule about boundary events.** One sits *on* a task, so every flow out of it
  starts inside a box. Its host is not an obstacle for it and not a crossing to report;
  `layout::endpoint_of` is where the router and the validator now agree about that.

**The glyphs are line segments, never a Unicode character.** `✉` is whatever the reader's font says
it is, and for a notation whose whole value is an unambiguous mark that is not a detail. What is
deliberately not there: a marker so fussy it stops reading at sixteen pixels. A gear at that size
is a smudge, so a service task gets a ring of spokes.

Said rather than left as a gap: a lane's name is horizontal, because rotated text is a change to
both writers and their bounds; and a message flow has no circle at its source.

## The catch-up — and the defect it found, again

The repository was then brought up to the language, the way `W-101` did on the tenth. It found the
same *kind* of thing, in the same place.

**Go-to-definition looked for `node` and nothing else.** It searched the literal keywords `node`
and `style`, so in the twenty-eight genres with a word of their own the jump silently did nothing.
It never read as a bug because returning `null` is also what "no such name" looks like. Anchor
completion had the narrower version of the same fault: it asked for `def.item`, the archetype's
*first* word, so a `scatter` in an `xy` file and an `event`, a `gateway` or a `data` in a BPMN one
were invisible to it.

Both now ask the archetype for `items()`. Two guards, both proven by reverting the fix.

Also swept: the README's command list and feature prose, `docs/language.md` (a worked BPMN section,
parsed and checked by the suite like every other fence), the printed manual — its `ortho` note said
the router avoids nothing, which had become false, and its `opacity` note now names the migration —
both extension READMEs, `editors/README.md`, the genre counts in `src/init.rs` and the manual, and
three new Patterns plus three Critical Warnings in `AGENTS.md`. The manual is at edition 1.3, and a
stray Markdown `**bold**` that Typst had been rendering as literal stars since edition 1.0 is gone.

## Two reports from the author, and the shape they shared

**`check` could be made to panic.** The report came with a line number, which is the fastest bug
report there is: `check.rs:2399`, index out of bounds when the length is zero. `resolved_nodes`
promises one style per node and returned an empty vector when the style registry would not build —
a second failure mode stacked on a first, since the broken style is already reported. Seventeen
checks walk that list beside `diagram.nodes`. Sixteen `zip`, so they quietly checked nothing, which
is the failure you never see. The seventeenth indexes, so `style a extends b` / `style b extends a`
in a `type state` file aborted the process. `W-027` says a library a document generator holds
inside its own process may not do that.

The interesting part is not the fix — a helper whose contract is "one per node" keeps it on the
failure path too, falling back to the base style. The interesting part is why the hostile corpus
missed it. It had broken styles. It had every genre. It never had the two **together**, and the bug
lived exactly at the crossing. It crosses them now, and crossing is what turns a test into a guard
rather than the memory of one bug.

**Completion got lost inside a group.** The same shape: a thing the server knew about, and a case it
had never been asked to cross. A `group_block` — what `group`, `component` and `activate` open —
holds statements as well as properties. The server called it a node, so inside a group you were
offered `fill` and `padding`, and no way to declare anything unless you already knew the word to
type. A container is *where a diagram nests*; it is the one block where declaring matters more than
styling.

It is `Block::Container` now, and rather than returning its property list it carries it down to the
statement level, so both lists are offered together with declaring sorted first. Anchors resolve to
the group's own members. Three smaller things fell out of reading the same function: `style node`
and `style edge` are themes for one side of the diagram — `check_styles` already warns when they
reach across, so completion stopped offering the crossing; `extends` is now offered after a style's
name, where it had been reachable only by knowing it existed; and a line holding nothing but
indentation is a statement position, which is the moment you most want the list and the one that
used to answer nothing at all.

Six guards between the two, every one proven by putting the old behaviour back and watching the
right tests fail. 539 tests.

## A rack, and then a room

`type rack` drew one cabinet. A datacentre has a row of them, and the author said so.

The mapping was already in the language and only had to be admitted: a container holds items, a rack
holds devices, so **a group is a rack**. Nothing new to learn, nothing new to spell. The bank runs
left to right in declaration order, each rack named over its own rails, each carrying its own U
numbers — because `units` on a group sets that one rack's height, and a row that mixes a half-height
network rack with full ones is the normal case rather than the exotic one. They stand on one floor,
so a short rack is short at the top, which is where a rack is short.

Two things fell out of that and are worth naming.

The **checker had to read the same frames the drawing does**. Two devices at U42 is a collision in
one rack and the ordinary state of affairs in two, and there is no way to tell those apart from a
flat list of nodes. `rack_frames` is therefore shared between `charts` and `check` rather than
written twice — the second copy is the one that drifts.

And a file that declares no group is **one unnamed rack holding everything**, drawn by the same code
down the same path. That is not a compatibility shim bolted on the side; it is the general case with
one frame in it. The proof was free: after the rewrite the whole suite passed, golden hash included,
and the rack drawing only moved when the *example* was rewritten to show a bank.

`units` written on a device is now a warning that says where it belongs. A property that reads as if
it did something is worse than one that is rejected.

544 tests.

## What a style's name means

Three reports, one root.

**The heading of a six-rack bank sat over the fourth rack.** `place_title` bounded the nodes, the
groups and the text, and left out the guides. But a rack's rails and unit rules *are* guides, a
chart's axes are guides, and a rack of a bank that is still empty is nothing else at all — so the
heading was centred on the two racks holding equipment and the six sets of U numbers, which is a
frame that has nothing to do with the picture. Lines are part of a drawing. They are in the box now.

**The rack's text was coloured by `style device`, and its horizontal rules could not be coloured at
all.** Those are the same fault seen from two sides: a diagram's own furniture — the rules a chart
draws behind its data, the numbers along them, the heading — belonged to nobody, so it was hardcoded
to the theme and, where it needed *some* owner, borrowed the items'. A heading is not a device.

`style grid` and `style title` name them. And naming them forced the question the language had been
avoiding since the first commit: **what makes a style name special?**

The answer was always there and was written down nowhere. The renderer looks up a fixed set by
itself — `node`, `edge`, `group`, and the genre's own item word — and everything else is a class
that paints where `.name` is written and nowhere else. That lived in `resolve`'s argument list. So
`style device` in a `type pie` file was a theme in the author's head and dead text on the page, and
there was no way to tell it from `style grid`, which was a typo until this commit made it not one.

`props::THEME_STYLES` is that set, and once it exists three things follow for free. `check` reports
a style that is on neither list — and names the near-miss, because a style called after *another*
genre's item word is somebody who knew exactly what they meant. Each theme declares the part of the
vocabulary it reads, so `fill` on a gridline is a warning rather than a line that draws nothing. And
the editor offers only that part, and offers the theme names themselves after `style `, which is
where the distinction becomes visible to somebody typing rather than to somebody reading the source.

The refactor's proof is in the goldens. Eighteen drawings moved, and all eighteen moved only their
heading: the rules and the ticks, rewritten to go through the same new code, came out byte for byte
what they were. A refactor that changes exactly what it meant to change is one you can believe.

552 tests.

## Two removals and a page

**The single-file playground went first.** `build.sh --inline` folded a 1.3 MB wasm module into the
HTML as a data URI so the page could be opened by double-clicking, and that was the right answer to
"a playground you cannot open is a playground nobody tries" back when the page was ninety lines of
inline script. It stopped being the right answer the moment the page deserved to be an application.

It is Svelte 5 and Vite on pnpm now, with a CodeMirror editor that knows the language, a diagnostic
dot in the gutter per line and the full list underneath, pan and zoom on the picture, a share link
that carries the source in the *fragment* — never sent to a server, and this page has no server to
send it to — and an SVG download.

Two new wasm entry points earned their place, and both for the same kind of reason the reference
manual is generated. `bgraph_check` exists because a file can render **and** have four warnings, and
a page that only knew whether the render failed could not show them. `bgraph_examples` exists
because the genre menu should be the crate's own `EXAMPLES` table: a playground offering a genre the
module cannot render, or missing one it can, is a playground that lies about the thing it exists to
demonstrate. Their JSON is hand-written, for the same reason the SVG writer and the PDF writer are.

**Then the native window went.** `src/window.rs`, the `window` feature, `minifb`, `--follow`,
`--server`, and the two-artefact release with its X11 and Wayland headers on the Linux runner. A
browser is on every machine this runs on; it works the same over ssh and on a second screen; and it
cost seventy-eight dependencies to say the same thing worse than `bgraph watch` already did. The
crate is back to what it claims to be: 24 lines of `cargo tree` with nothing on, 50 with everything.

One thing did **not** go with it. `resolve_generic_families` — the fix for `resvg` not consulting
fontconfig, so `sans-serif` fell to usvg's guess and a diagram came out set in a face nothing else
on the machine uses — lived in `window.rs` and was called only from there. The PNG writer never had
it, which means `-o diagram.png` had been carrying the original bug the whole time. It moved into
`render_png.rs`. A fix worth keeping does not leave with the code that happened to hold it.

552 tests.

## And then someone used it

The playground went out and came back the same evening with a screenshot: the line numbers were
brighter than the code they number.

CodeMirror paints its own gutter, and paints it for a *light* editor unless told otherwise. The page
had told it — in a stylesheet — and lost, because a stylesheet against a library's injected styles
is a specificity race the build order decides. It says so through an `EditorView.theme` now, held in
a compartment and reconfigured when the theme flips, which is injected above the base and wins
without arguing. The current line's number is the one exception: brighter, because that is the one
you are actually looking for.

Worth recording how the diagnosis went, because the first two guesses were wrong. Reading a
screenshot, the numeric literals looked unstyled too, and the hex colours looked like strings. Both
were false — a probe over the tokenizer showed every token carrying exactly the right tag, and
sampling the rendered pixels showed every colour exactly the palette's. Squinting at a screenshot is
not evidence. Sampling it is.

One thing changed on the way: the editor now mounts before the module does. A megabyte of wasm is
nothing on a warm cache and noticeable on a cold one, and blanking the whole page for it made the
one thing you came to do — type — wait on the one thing you did not.

## The manual stops illustrating a language it no longer describes

`docs/manual.typ` embedded nine rendered `.svg` files that sat beside their `.bd` sources. The
argument for that was written down in `typst/README.md` and it was a decent one: the source is
versioned next to the picture, both are reviewable, and the document build stays a document build.

The measurement settles it. After today's work — the rack bank, the theme styles, the heading that
stopped taking an item's colour — **eight of the nine were out of date**. The manual was describing
one language and drawing another, and nothing anywhere would have said so. A picture checked in
beside its source is a copy, and a copy is a thing that stops being true.

It reads the `.bd` through bgraph's own Typst plugin now, which is the plugin's own argument made on
the plugin itself. A diagram that stops parsing stops the build, with the compiler's message and the
line of the document that asked for it — the same thing `check` does on the command line, and better
than a document that ships with a hole where a diagram should be.

The cost is honest and worth naming: the manual now needs a wasm module that is not checked in.
`compile.sh` builds it when it is missing, so `./compile.sh docs/manual.typ` is still one command on
a fresh clone.

A test refuses both halves of the old arrangement: a rendered picture back in that directory, and a
`.bd` the manual never draws — because an orphan source is one nobody renders, so nobody notices
when it breaks.

553 tests.

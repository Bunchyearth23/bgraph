## 1. The new label warning — classification and evidence

### The diagnostic

The architecture warning is the check in `src/check.rs:565-572`:

```rust
out.push(Diag::warn(
    edge.span,
    format!(
        "the label `{text}` is drawn over `{}`, which is painted after it — \
         widen the gap, or move the label with `label-offset`",
        node.id
    ),
));
```

It is the only diagnostic in the tree that names a **node id** next to the word
"label", and its span is the **edge**, so `file:line:col` points at the edge
declaration — consistent with the report's "a label overlapping `authapi` at
line 199". Reproduced verbatim (identical text, old and new binary):

```
/tmp/w172/cases/r0.bd:4:1: warning: the label `query` is drawn over `a`, which is painted after it — widen the gap, or move the label with `label-offset`
```

The other candidates were excluded on the evidence: `src/check.rs:577` names an
*annotation's text* ("overlaps the text `{}`"), `src/check.rs:592` names another
label or a group title, and `src/check.rs:701` is a box-over-box conflict with
no label in it.

### The check did not get stricter

`git show 79d2d80 -- src/check.rs` adds exactly two things: the `legend`
needs-a-position warning and the `font` two-sizes warning. The "drawn over"
diagnostic is byte-identical at `79d2d80^` (`git show 79d2d80^:src/check.rs`
line 491) and at HEAD. So the warning is **not** a stricter check catching an
old condition, and it is **not** a false positive: the geometry really does
overlap.

### What did change: the cylinder's height

`git show 79d2d80 -- src/layout.rs`:

```diff
-        Shape::Cylinder => h += 14.0,
+        // The top ellipse takes two cap radii and the bottom takes one.
+        Shape::Cylinder => h = (h / (1.0 - 3.0 * 0.16)).min(h + 3.0 * 14.0),
```

Measured on one source, `node db "Database" { shape: cylinder }` (one line,
font 14, padding 14 → text space 46.9):

| | `79d2d80^` | HEAD |
|---|---|---|
| node height `h` | 60.9 | 88.9 |
| cap `ry` | 9.74 | 14 |
| readable body `h − 3·ry` | 31.68 (text overflowed by 15.2) | 46.9 (exact) |

The new height is *correct*: the drawn cylinder is an ellipse cap at the top
(two radii of it are inside the box) and a flat base one radius above the
bottom edge (`src/render_svg.rs:1405-1428`), so the text needs `h − 3·ry`
(`src/render_svg.rs:1956`, `src/layout.rs:265-272`). The old `+14` reserved too
little — that is the point-4 bug the patch fixes.

## 2. Point 3 — re-derived, not inherited

The claim to test is "the sequence frame at negative x is not clipped".

The rule in the code (`src/render_svg.rs:33-43` and `1013-1033`): `canvas()`
computes `dx = pad − min_x` over `bounds()`, and `bounds()` **includes the
frames** (`boxes.extend(layout.groups.iter().map(|g| outer(g.rect, &g.style)))`).
Therefore the leftmost geometry of any kind lands exactly at `pad` inside the
canvas and nothing can be cut off by a negative x.

Measured on a reproduction with a frame that reaches left of the first
participant (`/tmp/w172/cases/seq.bd`):

```
viewBox="0 0 567.46 197.04"   translate(256.46,32)
frame rect x="-224.46" → visible left edge = -224.46 + 256.46 = 32.00  (= the default padding)
```

The user's numbers satisfy the same identity: `−175.04 + 211.04 = 36`, i.e. the
frame's visible left edge is 36 units from the canvas edge — inside the canvas,
not clipped. The regression that pins it is
`tests/patch_101.rs:56-77` (`frame.x + dx >= 0.0 && frame.right() + dx <= width`),
and it passes.

**Point 3 is a false positive, re-derived:** the negative `x` is a *layout*
coordinate; the SVG's `translate` is derived from the same bounds, so the frame
is inside the `viewBox`. Nothing is clipped and nothing needs fixing.

The report's row: *"Restoring `bend: 12` on the infrastructure edge style
rendered successfully… An exact source before the workaround is still needed to
attribute the reported gaps."* The repository holds the **proxy** (the regression
that samples a rounded stroke), not the **subject**.

What is already covered, and passes
(`cargo test --offline --features png --test patch_101` → 9 passed, including
`rounded_waypoints_with_an_empty_label_have_a_continuous_raster_stroke`):

```bgraph
  place b at (300, 50)

```

**Only the user can advance point 5.** What to ask for, precisely:

1. The infrastructure `.bd` **as it was before the workaround** — the file with
   `bend: 12` on the edge style, not the one with it removed. The file itself,
   not a screenshot of the source.
2. The rendered artefact that shows the gaps (the SVG or PNG they saw), since
   the gaps are a property of the stroke at a given raster scale.
3. The exact command and the version: `bgraph --version`, whether `--embed-font`
   or a `--theme` was used, and whether the output was SVG or PNG.

What is **not** needed and should not be asked for: a minimised file. The
question is whether the *original* file still shows gaps under the current
build; a minimised file would answer a different question.

If the original file is supplied and still shows gaps, the next hypotheses to
test, in order, are the ones the proxy does not cover: the label plate's own
background against the stroke (`src/render_svg.rs:1194-1204`), a `bend` radius
larger than the elbow's shorter leg, and the stroke width crossing the raster
grid at a fractional scale.

## 4. Point 12 and `X-005` — the exact link

Point 12 (report row): the `new_uat` title exceeds its plate; the plate is
246.95 units while DejaVu Sans Regular advances at size 12 are about 275.67;
"font embedding occurs after solving and does not change the advance table".

`X-005` (`docs/INDEX.md:217`) is: *"Estimated advances can leave text outside
its intended bounds."* The link is **the same root cause, not a neighbour**:

* Node sizes, wrapping and label placement are measured with the crate's
  advance table (`src/layout.rs:267` `text_width` → `advance`), which is a
  Helvetica-class *estimate* (`D-026`).
* `--embed-font` is applied when the document is written
  (`src/main.rs:585-600`), long after the layout was solved, so it cannot
  change any solved size. `docs/API.md:43-46` states this contract: *"Embedding
  a font makes that face portable; it does not rerun layout or move the solved
  nodes and frames… still use the built-in advance estimates (`X-005`)."*
* The 2026-10-22 work narrowed `X-005` to *explicit-family* group-title plates
  and title canvas bounds: where the title names the embedded family first,
  that face's `hmtx` advances are used (`src/render_svg.rs:1004-1012`, and its
  uses at `981`, `1057`, `1198`). Everything else — global sizing, wrapping,
  shaping, kerning, installed-font metrics — is still estimated.

So point 12's first fixture (a title measured with *local* font metrics) and the
second fixture (an explicit-family title that still overflowed on 2026-10-21)
are **instances of `X-005`**, and closing point 12 requires the global
measurement contract that `X-005` names. That work belongs to the `X-005`
owner; nothing here touches it.

**Findings**

1. **The notes were stale against HEAD (fixed here).** "Text measurement
   remains approximate, including group title plates" was true on 2026-10-21
   and no longer is: the 2026-10-22 work measures group-title plates and title
   bounds with the embedded face's advances when the title names that family
   first. The notes now say exactly that.
2. **The new architecture warning was absent from the notes (fixed here).** A
   user reading the notes would have met a warning in their own file that the
   patch never mentioned. The notes now state that the taller cylinder moved
   the solved geometry, that the diagnostic is truthful, and that the repair is
   in the file.
3. **"without changing the grammar" was no longer true (fixed here).** The
   `W-172` delta added no statement, but the explicit `legend` blocks landed in
   the same window (`src/syntax.pest` `legend_block`/`legend_entry` in
   `3567c31`, tree-sitter mirror `4f45a50`). The notes now say so instead of
   claiming the grammar is untouched.
4. **The cylinder grew — and the notes did not say so (fixed here).** Every
   cylinder is now up to 1.9× the height of its text space, so a file that
   placed boxes by absolute coordinates can collide with its own boxes. The
   notes now say that a file may need its absolute placements reviewed. This
   is the same cause as the architecture warning.
5. **Scope.** The notes describe the `W-172` delta only. If 1.0.1 is cut at
   HEAD it also carries `W-166`–`W-171` and `W-173`–`W-174` (margins, BPMN
   captions, editor previews, Venn geometry, legend blocks, the README
   onboarding guard) and the licence change — none of which these notes
   describe. There is no `v1.0.0` tag (`git tag -l` → `v0.1.0` only), so 1.0.0
   was never published and "1.0.1" has no released baseline to be a patch
   against. **This is a decision for the user**, not a defect: either the
   notes stay the report-delta and the release is announced as such, or the
   notes grow to cover the whole window.
6. **Packaging hygiene (minor).** The crate package ships 489 files including
   `.agent/analysis/**` (there is no `include`/`exclude` in `Cargo.toml`). Harmless
   for a binary distribution; noise in a source crate.
7. **Two warnings remain in the user's own infrastructure file** (isolated
   `pve` and `sandbox` hosts, 2 → 2 across the patch). They predate 1.0.1 and
   are the author's to fix.

# W-166 — external margins and sequence frame spacing

## Request and diagnosis

The user supplied a sequence screenshot whose first `Demands` frame touches
the participant headers, and requested CSS-like margins for multiple genres.
The old sequence formula placed the first message at `header_bottom + 0.9 * row`
and the frame top at `first_message - (0.62 * row + 14)`. With the default
row of 46, the frame began 1.12 units above the headers' bottom edge.
The original `.bd` and names of other affected genres were requested but
were not supplied during this change; the pictured sequence was reconstructed.

## Contract

- `margin`: one, two, three or four finite nonnegative values, in CSS side
  order; `margin-top/right/bottom/left` override individual sides through the
  normal cascade. Zero is the default. No negative margins, `auto` or collapsing.
- Distances are drawing units. Unit suffixes remain advisory, including `%`;
  there is no parent-relative percentage calculation.
- Relative placement, implicit flow and row/column gaps add the adjacent
  margins. Absolute coordinates and explicit alignments address visible boxes.
- Containers include child margins as well as padding and visual overhang.
  Canvas bounds include root margins, shared by SVG, PDF and PNG.
- Supported by all nine declared-layout genres and by sequence participants
  and frames. Other managed genres reject these properties explicitly and
  do not offer them in completion. Activation bars and edges are not margin boxes.
- Sequence scheduling reserves frame titles, external vertical margins and
  activation extents before positioning messages. Parent frames include
  descendant messages and reserve bands around nested frames. Participant
  columns account for measured width, multiline labels and margins.
- The solver and post-layout validator share the same margin separation rule.

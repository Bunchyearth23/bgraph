## 1. Which nine types accept `margin`, and how `sequence` reserves room

The predicate is `src/spacing.rs:64`:

```rust
pub(crate) fn supported(def: &ArchetypeDef) -> bool {
    def.layout.accepts_layout_block() || def.name == "sequence"
}
```

`accepts_layout_block` is true only for `LayoutStrategy::Declared`
(`src/props.rs:1678`). The nine declared archetypes, read out of
`src/props.rs` with

```
awk '/^    ArchetypeDef \{/{...} /layout: LayoutStrategy::Declared/{print NR": "name}' src/props.rs
```

```
1783:         name: "free",
1831:         name: "class",
1863:         name: "block",
1882:         name: "er",
1908:         name: "state",
2146:         name: "harness",
2191:         name: "bpmn",
2250:         name: "network",
2345:         name: "requirements",
```

So the supported set is **free, class, block, er, state, harness, bpmn,
network, requirements** plus **sequence** — ten in all. Every other managed
genre is refused by `check::check_margins` (`src/check.rs:950`), which is also
what keeps `margin` out of completion for them
(`props::item_table`, `src/props.rs:785`).

`sequence` reserves room in `src/charts.rs`:

* participants: `header_bottom` is pushed down by `margin.top + h +
  margin.bottom` and the column pitch is widened by `margin.left +
  margin.right` (`src/charts.rs:4846-4852`);
* frames: the band above the first message is
  `max(nominal, band + 6, title_size * 1.8 + first_label + 4)` and the band
  below the last message is `max(nominal, padding, last_label + 4)`, where
  `first_label`/`last_label` are the *measured* label extents
  (`src/charts.rs:4911-4927`) — this is the 2026-10-20 fix;
* nested frames: a parent's band grows by the child's own margin plus its
  padding (`src/charts.rs:4948-4959`), and a parent's horizontal bounds grow
  by the child's left/right margin (`src/charts.rs:5135-5148`).

# W-159 — explicit geometry capability matrix

## Implementation

`ArchetypeDef.layout` is the single geometry contract. `LayoutStrategy::Declared`
selects the common declared-layout solver. `ArchetypeManaged(callback)` carries
its renderer, so capability and dispatch cannot disagree. `layout::solve` calls
this callback rather than maintaining an independent match on genre names.
The old `DECLARED_LAYOUT_ARCHETYPES` list is removed.

The classification is exhaustive over the 30 default archetypes:

- Declared (9): free, class, block, er, state, harness, bpmn, network, requirements.
- ArchetypeManaged (21): pie, packet, kanban, journey, radar, rack, venn, gitgraph,
  orgchart, mindmap, treeview, bytefield, treemap, quadrant, wave, sankey, bar, xy,
  sequence, gantt, timeline.
- Hybrid (0): no renderer currently reads named layout guides. The reserved
  `Hybrid { solver, guides }` variant keeps its allowed guide names explicit.
  The current grammar contains no named guide statements, so it grants no
  entity layout statements. No new guide syntax or unimplemented support is claimed.

Validation rejects every global or group-local layout block in managed genres,
including empty blocks. The 21 managed renderers also ignored `diagram.notes`;
these now produce an error at the note span, rather than successful output that
silently omits the annotation. Groups and edges retain their genre semantics.

LSP completion offers the six canonical entity relations only inside a supported
layout block; managed genres offer neither layout blocks nor notes. Top-level
layout completion inserts an actual block, and entity relations are no longer
offered as standalone declarations. Strings and comments stay quiet.

Generated reference documentation includes the complete matrix and each genre's
capability. The machine vocabulary schema adds `layoutCapability`,
`layoutStatements`, and `layoutGuides`, all derived from the same strategy.
No feature-dependent renderer callback exists outside its archetype's feature gate.
